# App launcher

Date: 2026-10-14 17:15 EDT

## Context

A way to open apps: a Start-style launcher on the logo key, ahead of any taskbar. Custom entries are added the
standard way, as XDG desktop entries.

What was decided is in [apps/launcher.md](../intents/apps/launcher.md) and
[apps/desktop-entries.md](../intents/apps/desktop-entries.md).

## Tasks

- [x] Desktop-entry parsing as pure code with unit tests (locale names, hidden entries, escapes, Exec field codes, match ranking)
- [x] App list from `$XDG_DATA_HOME` and `$XDG_DATA_DIRS`, the user's copy of an entry winning, TryExec respected
- [x] Icons from the user's icon theme, its Inherits chain, hicolor and pixmaps (comma-separated `index.theme` lists; icons outside the Applications context found too)
- [x] Windows-11-style panel: search field, list with icons, scrollbar, empty state, footer
- [x] A lone Windows-key tap and Super+Space open and close it; the logo key used as a modifier never opens it
- [x] Keys (type to filter, arrows, Page and Home/End, word and line deletion, Enter, Escape) and pointer (hover, click to launch, wheel, click outside to close)
- [x] Launched windows open where any new window does; `Terminal=true` runs inside `$TERMINAL`
- [x] Adding an item the standard way: a `.desktop` file in `~/.local/share/applications`, validated with `desktop-file-validate`, documented in the README
- [x] Counts read "1 app" and "Tiled 1 window"
- [x] Launcher scenario in `tests/scenarios/launcher.c`, including a custom entry that is listed and launched
