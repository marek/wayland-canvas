# Packaging

Date: 2026-10-14 21:50 EDT

## Context

The build system is to produce a `.deb` for Debian and Ubuntu and a
`.pkg.tar.zst` for Arch and Arch-based distributions, with one install flow
that asks whether wayland-canvas should become the default session. Removing
the package — through the installer or with the system's own package manager
— must reverse that default when it was set, and must never leave the login
pointing at a session that no longer exists.

Design settled for this body of work:

- The package formats are built by meson run targets `package-arch` and `package-deb`,
  artifacts under `build/packages/`. The Arch package is built by `makepkg` from a
  tarball of the local source tree (the wlroots subproject included, so the build
  needs no network). The .deb is built inside a rootless Debian root filesystem,
  downloaded once and cached under `tmp/`, entered with user namespaces.
- Packages never prompt: pacman forbids prompts in install scripts, and one installer
  flow (`tools/install.sh`) serves both formats. It asks whether to make wayland-canvas
  the default and runs the tool; `--uninstall` restores the default and removes the
  package.
- The default-session tool `wayland-canvas-session` (`status`, `set-default`,
  `restore`) ships with both packages. It detects the display manager — SDDM
  (autologin `Session=` and the remembered last session), GDM (AccountsService),
  LightDM (autologin and the greeter's remembered session), greetd (the
  `default_session` command) — and records exactly what it changed under
  `/var/lib/wayland-canvas/session-default/`, so `restore` returns every file byte
  for byte. A `--root` prefix makes it testable against fake roots.
- The removal hooks (`pre_remove` on Arch, `prerm` on Debian) run `restore`
  themselves, so a plain package-manager removal also un-does the default.

The contract is written down in
[../intents/workspace/packaging.md](../intents/workspace/packaging.md).

## Tasks

- [x] `packaging/wayland-canvas-session`: `status` / `set-default` / `restore` for SDDM, GDM (AccountsService), LightDM and greetd; journal under `/var/lib/wayland-canvas/session-default`; `--root` prefix for testing
- [x] Session file `packaging/wayland-canvas.desktop` installed to `share/wayland-sessions` by meson
- [x] Packaging suite `tests/test_packaging.sh` (meson suite `packaging`): set-default then restore leaves every file byte-identical for each display manager; restore with nothing recorded is a no-op; repeated set-default is idempotent; a missing previous session is restored as it was
- [x] `tools/package-arch.sh` behind `ninja -C build package-arch`: a `.pkg.tar.zst` under `build/packages/`, file list inspected (binary, session file, tool, licence)
- [x] Arch removal hook: `pre_remove` runs `restore` (the `.INSTALL` scriptlet is in the built package; `restore` itself is proven by the suite)
- [ ] `tools/package-deb.sh` behind `ninja -C build package-deb`: a `.deb` built inside a cached rootless Debian root filesystem, the release chosen by a C++26 probe, `Depends` computed by `dpkg-shlibdeps`
- [ ] Debian removal hooks: `prerm` runs `restore`, `postrm purge` clears `/var/lib/wayland-canvas`
- [ ] The `.deb` installed inside the disposable Debian root filesystem: `wayland-canvas -h` runs there and `set-default`/`restore` work against that root's display-manager configuration
- [ ] `tools/install.sh`: builds or takes the distro's package, installs it with the system package manager, asks whether to make wayland-canvas the default; `--uninstall` restores the default and removes the package
- [ ] Docs: `docs/intents/workspace/packaging.md` and its index row, a README install section, the build-and-run rows for the package targets
- [ ] Verified end to end: a warning-free build, `tools/check.sh` green (unit, scenarios, packaging suites), both artifacts built, their paths and sizes recorded in this plan

## Notes for verification

- This machine is Arch with `makepkg` but no `dpkg-deb` and no sudo/docker: the Arch
  package is built and only its file list inspected (never installed here); every
  install/uninstall proof of the `.deb` happens inside the disposable Debian root
  filesystem under `tmp/`.
- The real `/etc`, `/var/lib` and `/usr` of this machine are never touched; the
  session tool is proven against fake roots and that root filesystem only.
